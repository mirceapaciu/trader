### Configuration critique (methodology §2)

1. **Evidence chain vs horizon (S14, confirmed).** Cards claim `time_horizon = swing_1d_5d`, but a
   card is only created when **3 distinct articles** for the same (ticker, strategy, direction)
   arrive within **`evidence_collection_max_minutes = 120`**. Measured cadence: qualifying
   same-cluster articles arrive hours apart, not within 2 h. 8 evidence windows collected 3
   articles but expired first; 24 more stalled at 2. A multi-day thesis gated on a 2-hour news
   burst only fires on the fastest-breaking stories.
2. **Staleness gate is dead config.** `max_evidence_age_minutes = 180` can never bind while the
   collection window is 120 min (+3 min pipeline delay). If the collection window is widened, the
   staleness gate must be raised in the same change or it silently rejects the new cards.
3. **Post-expiry swallowing defect** (`thesis_builder/repository.py:284-302`): an analysis arriving
   after the 120-min deadline is appended to the window it just expired and returns `None` — it
   does **not** seed a fresh `collecting` window. The first article of every new cluster after an
   expiry is thrown away. A ticker with steady 90-min news cadence can accumulate windows of 2
   forever and never produce a card at any `required_evidence_count` ≥ 3.
4. **`min_confidence = 0.6` never binds** (S7 flavor): 0 of 348 analyses rejected
   `below_min_confidence`; both cards landed at 0.783. The gate is uninformative as configured —
   gpt-4o-mini's confidences cluster above it.
5. **Card expiry uses wall clock, not sim clock:** both card snapshots show
   `card_expires_at = 2026-07-08 03:24/03:25` (run time + 6 h) for cards created 2026-06-15. In-sim
   expiry semantics are therefore not exercised; live-expiry population stats from regeneration
   runs are meaningless. (Known workaround for the `expires_at > NOW()` signal-load check; still an
   incoherence worth recording.)
6. **Sizing floor removed half the population:** the MU card was risk-blocked
   `size_below_one_share` — live-parity sizing (`max_loss_usd / |entry − stop|`, capped by
   `max_position_usd = $1,000`) produced < 1 share. With $10k capital and 2-card populations,
   a single sizing block erases 50% of the sample.

## Recommendations (ranked)

**Generation:**
1. **Widen `evidence_collection_max_minutes` to day scale (720–1440) and raise
   `max_evidence_age_minutes` above it in the same change.** This is the single highest-impact
   knob: 2 → ~11–15 cards on the same analyzed article set, already empirically corroborated by
   run `bt_8f4a609e`.
2. **Fix the post-expiry swallowing defect** — on expiry, seed a new `collecting` window with the
   arriving analysis. Roughly doubles yield at tight windows; strictly beneficial at any setting.
3. **Raise the run token budget to ≥1.1M** (or pre-filter `instrument_not_subject` articles more
   cheaply — 42% of LLM spend produced `instrument_not_subject` rejections) so a two-week window is
   actually covered. Also: a run that exhausts its budget should not finish `status=completed`
   without a visible flag; surface `budget_exhausted` in the run row/UI.
4. Revisit `min_confidence = 0.6` (never binds) — either calibrate it or stop treating it as a gate.

**Trading:** none yet — no trade sample. Re-verify after the generation fixes on a **holdout
window** (not 2026-06-15..26, which this analysis has now consumed for tuning).
