### Why all trades were blocked

Both trades: `exit_reason = risk_blocked`, `risk_block_rule = size_below_one_share`. Live-parity
sizing is `qty = floor(max_loss_usd / |entry − stop|)` clamped by
`floor(max_position_usd / entry)` (`trade_executor/pipeline.py::size_position`). Measured inputs
at the two entry attempts:

| | 06-22 entry | 06-25 entry |
|---|---|---|
| MU open | $1,196.21 | $1,233.00 |
| ATR20 | ≈ $93.1 | ≈ $92.9 |
| stop distance (1.5 × ATR) | ≈ $139.6 | ≈ $139.3 |
| qty by risk: floor(120 / stop_dist) | **0** | **0** |
| qty by notional: floor(1,000 / entry) | **0** | **0** |

MU is blocked **twice over, structurally**: its per-share price exceeds the whole
`max_position_usd = $1,000` cap, and its 1.5-ATR dollar risk (~$139) exceeds the whole
`risk_max_loss_usd = $120` box. No MU card can ever be sized to 1 share under this configuration,
at any confidence, on any day in this regime. Combined with the evidence-gate finding: the
generation config concentrates all card yield on exactly the ticker the trading config can never
execute. Run-level outcome (0 trades) is the deterministic product of the two configs, not noise.

### Configuration critique (new items this run)

1. **Risk box vs instrument universe (S11/S14 flavor, confirmed):** `max_position_usd = $1,000`
   and `risk_max_loss_usd = $120` silently exclude every four-digit-price ticker (MU at ~$1,200;
   ATR ~$93). Integer-share sizing means the watchlist's high-price names are dead weight for the
   whole pipeline. Options: raise the caps, support fractional shares, or add a generation-side
   tradeability filter (`price ≤ max_position_usd`, `1.5·ATR ≤ max_loss_usd`) so cards are not
   produced for unsizeable instruments.
2. **Budget arithmetic unchanged (repeat):** ~1,390 tokens/analysis; a 12-day window at this news
   volume needs ≈ 1.3M tokens. 500k covers ~4.6 days. The `bt_2373c76a` recommendation (raise
   budget or pre-filter the 37% `instrument_not_subject` spend) is still unapplied. The LLM cache
   (4b629dd) did not help because this run used a fresh window with no cached overlap.
3. **Evidence gate unchanged (repeat, S14):** 120-min collection window still incoherent with
   `swing_1d_5d`; the prior analytic sweep (validated against `bt_8f4a609e`) showed ~11–15 cards
   at 720–1,440 min on a same-size analysis set.
4. **`min_confidence = 0.6` still never binds:** 0 of 356 analyses rejected below it; both cards
   at 0.85.
