# 260707-02 Backtester must persist per-trade excursion diagnostics required by backtest verification

## Problem Statement

The backtest verification workflow (`docs/design/backtest-verification-methodology.md`, executed
by the `verify-backtest` skill) depends on per-trade path diagnostics that the Backtester does
not currently compute or persist: maximum favorable/adverse excursion (MFE/MAE), fixed-horizon
gross returns (including day-scale horizons matching the cards' `swing_1d_5d` time horizon), a
flag for bars spanning both bracket levels, and the bar-coverage ratio. Without these columns:

- the headline edge statistics (`edge_gross` at 2 h and at the cards' stated horizon) cannot be
  computed reproducibly — suspects S6 (no directional edge) and S14 (horizon incoherence) are
  untestable;
- "edge existed but the exit destroyed it" (S4) cannot be distinguished from "no edge," because
  nobody records how far a trade moved in favor before being stopped out;
- the intrabar tie-break exposure (S3) and per-trade data-quality gating (S10) have no data.

The simulation already walks every bar of every trade in `_find_exit`, so these metrics are
nearly free to compute at simulation time. Recomputing them afterwards (as an external tool)
would re-fetch and re-walk all bars — slow, duplicated logic, and a second interpretation of
intrabar semantics that can drift from the engine's.

The design is already documented on the Backtester specs; this issue tracks the implementation.

## Expected Behavior

For every filled trade (all `exit_reason` values except `not_filled` and `risk_blocked`), the
Backtester computes during simulation and persists on `t_backtest_trades`:

- `mfe_pct`, `mae_pct` — maximum favorable/adverse excursion over the holding period, signed by
  direction, at ±1-bar resolution (bar high/low relative to entry price).
- `time_to_mfe_seconds`, `time_to_mae_seconds`.
- `horizon_returns_json` — signed gross close-to-entry returns at each configured post-entry
  horizon (`BACKTESTER_EXCURSION_HORIZON_MINUTES`, counted in regular-trading-hours minutes),
  cost-free and exit-free (measured even past the exit, bounded by the run window); a horizon is
  null when the window ends before it is reached.
- `both_brackets_in_one_bar` — true when any bar in the holding period spans both the stop and
  the target.
- `bar_coverage_ratio` — bars present / bars expected (at the run's `bar_interval`, regular
  trading hours) between entry and exit.

Constraints:

- No look-ahead is introduced: horizon returns use only bars whose interval has closed by the
  simulated clock, within the run window; they are diagnostics and must not influence entry,
  exit, sizing, or risk decisions.
- Columns are nullable and added idempotently (`ADD COLUMN IF NOT EXISTS`), so existing run rows
  remain valid; old runs simply have null diagnostics.
- Horizon configuration is env-owned (`BACKTESTER_EXCURSION_HORIZON_MINUTES`) with the documented
  default including day-scale horizons.
- The additional bar reads for post-exit horizon returns reuse the already-prefetched bar series;
  no new provider traffic.

## Acceptance Criteria

- `t_backtest_trades` gains the six columns above (idempotent schema change) and the engine
  populates them for every filled trade in both timing scenarios.
- For a hand-constructed bar fixture, MFE/MAE, times-to-extreme, horizon returns, bracket-span
  flag, and coverage ratio match hand-computed values for both `buy` and `sell` directions.
- A horizon past the run window's end yields null for that horizon, not an error.
- `not_filled` and `risk_blocked` trades carry null diagnostics.
- Simulated entries/exits/P&L are byte-for-byte unchanged versus the previous engine on the same
  fixture (diagnostics are pure additions).
- Run duration on a typical replay window does not regress materially (single-pass computation in
  the existing bar walk).

## Test Plan

- Unit tests in `tests/product_components/backtester/` (fakes, no external deps):
  - buy and sell trades over a crafted bar series with known MFE/MAE and horizon values;
  - a bar spanning both brackets sets `both_brackets_in_one_bar = true`;
  - missing bars in the holding period reduce `bar_coverage_ratio` accordingly;
  - horizon truncation at window end yields nulls;
  - regression: existing engine behavior tests pass unchanged.
- Schema bootstrap test: re-running `db/schema.sql` on an existing database succeeds
  (idempotent).
- `uv run pytest -m "not integration"` passes.
- End-to-end: one replay run over a real window; spot-check a few trades' diagnostics against
  bars queried directly from `market_data`.
