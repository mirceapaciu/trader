# 260715-05 Story assignment is taken from the LLM on trust; a misassigned article joined an unrelated story's window and its evidence published on the card

## Problem Statement

260715-01 made story identity a load-bearing input: which window an analysis joins decides
which evidence corroborates which card. That decision rests entirely on one `gpt-4o-mini`
call with a 120-token output cap, taken on trust. `_resolve_story_target` accepts
`assignment.target` verbatim (`repository.py:635`), and `parse_story_assignment_result`
(`llm_client.py:479`) validates only enum shape — that the target is `window:<id>` /
`card:<id>` / `new_story` and appears in the candidate list. Nothing, deterministic or
otherwise, ever checks whether the article is actually the same story as its destination.

The assignment prompt itself is explicit about the contract
(`llm_client.py:696-700`): *"Decide whether the incoming article is the same underlying news
event as one existing story candidate … Do not match merely because ticker, sentiment,
strategy, or direction are the same."* When the LLM violates that instruction, the violation
flows straight through to a satisfied window and a published signal.

This is structurally the same defect class as 260714-03, one layer up. That issue's diagnosis
— "the `direct` label itself is taken from the LLM on trust" — was resolved with a
deterministic post-LLM backstop (`_normalize_analysis_result`). Story assignment has no
equivalent. The fail-open path makes it sharper: on transport failure the analysis falls back
to *"the oldest collecting window for the key"* (`repository.py:645-651`), which is
story-blind by construction.

A designed checkpoint exists downstream and is dark: the 260709-06 strong-model synthesis pass
at window satisfaction (`repository.py:492-554`) can reject an incoherent window — but
`THESIS_BUILDER_SYNTHESIS_ENABLED` appears in no env file, defaults to `False`
(`settings.py:125`), and `thesis_builder.t_card_synthesis_verdicts` has **zero rows ever**. So
today there is no live layer between a story misassignment and a published signal.

## Expected Behavior

1. **Story assignment gets a verification layer.** `chosen_target='window:<id>'` /
   `'card:<id>'` is treated like the self-reported `direct` label was in 260714-03: an
   unverified claim. Options, not mutually exclusive:
   - **(a) Deterministic post-assignment check** — cheap textual/entity overlap between the
     incoming article and the target's `story_narrative`; on failure, downgrade to `new_story`
     (which, with 260715-04 in place, rejects indirect evidence outright) and record the
     downgrade for audit, mirroring `direct_subject_text_mismatch_downgraded`.
   - **(b) Enable the tier-2 synthesis pass** (260709-06) with an explicit story-coherence
     instruction: the synthesis dossier already contains all selected evidence bullets; the
     verdict must reject windows whose evidence spans distinct underlying events. This
     catches misassignments at the last gate before a card, at strong-model quality.
   The issue owner chooses the mix; the acceptance criteria below are mechanism-agnostic but
   require at least one live enforcement layer.
2. **The fallback path is included.** `assignment_source='fallback'` (oldest collecting window
   for the key) is story-blind; whatever verification lands must apply to fallback placements,
   not only `matched` ones.
3. **Audit trail.** Verification outcomes are persisted (per-assignment audit column or verdict
   row), so cross-story admission rates are measurable before/after, like the 260714-03
   downgrade audit.
4. **Regeneration parity.** Live processing, historical reprocess, and regeneration backtests
   apply the same verification, so sim funnels stay comparable. If synthesis is enabled, note
   the regeneration cost implication before production enable.
5. **Dedupe interaction acknowledged.** Fixing coherence does not fix 260709-07: a window can
   still satisfy on the same story counted via two feeds plus nothing else. Cross-reference
   only; no scope creep.

## Acceptance Criteria

- Replaying the 9119 → 9175 → 9176 sequence against a clean NVDA state produces **no card**:
  9176 is either routed away from window 2456 by verification (then rejected
  `indirect_no_anchor_evidence` under 260715-04) or the window is rejected at synthesis; the
  Nokia story remains free to satisfy with genuinely corroborating third evidence.
- A genuinely same-story article (e.g. 9175 relative to 9119: same Nokia event, second feed)
  still matches its window — the verification layer must not shatter every story into
  singleton windows.
- The enforcement outcome is queryable per assignment (audit column or verdict row), and a
  baseline cross-story rate over a recent production window is reported before/after.
- With `THESIS_BUILDER_STORY_SCOPING_ENABLED=false`, behavior is unchanged.
- If option (b) is chosen: `t_card_synthesis_verdicts` receives rows in production, and a
  window whose selected evidence mixes two underlying events is rejected with a
  story-coherence reason code.

## Resolution

Status: resolved on 2026-07-15.

Root cause: `_resolve_story_target` accepted a shape-valid LLM or fallback target as the final
story destination. The assignment audit recorded the selected target, but no deterministic layer
checked whether the incoming article shared the target story's underlying event.

Fix:
- Added deterministic story-assignment verification for `window:<id>` and `card:<id>` targets.
  The verifier compares distinctive tokens from the incoming article/story fields with the
  target `story_narrative`; generic market words and the ticker itself do not count.
- Off-story matches are downgraded to `new_story` with
  `verification_status='downgraded'` and
  `verification_reason_code='story_text_mismatch'`.
- The same verifier runs for `assignment_source='fallback'`, so fail-open oldest-window
  placement no longer bypasses story coherence.
- `t_story_assignments` now persists both `chosen_target` and `resolved_target`, plus
  `verification_status`, `verification_reason_code`, and bounded
  `verification_details_json` for audit and baseline measurement.
- With 260715-04 in place, downgraded indirect evidence is rejected as
  `indirect_no_anchor_evidence` and does not join or satisfy the unrelated window.
- Same-story assignments with distinctive overlap still pass and join the existing window.

Verification:
- `uv run pytest tests/integration/test_thesis_builder_integration.py -q` -> `15 passed`
- `uv run python -m py_compile src\product_components\thesis_builder\repository.py tests\integration\test_thesis_builder_integration.py`

Remaining risk / follow-up:
- This does not address 260709-07; duplicate coverage of the same story across providers can
  still count as multiple corroborations.
- The deterministic verifier is intentionally conservative and auditable. Future calibration
  can tune its token filters using `verification_details_json` without changing the assignment
  storage contract.

### Calibration follow-up (2026-07-16, commit c324d63)

The `verify-story-assignment` audit built a labeled corpus of the full pre-fix backlog
(ids 1–66; `tests/product_components/thesis_builder/fixtures/story_assignment_corpus.jsonl`,
41 rows) and replayed the deterministic verifier against it
(`docs/verification-runs/story-assignment/260716-stage6-replay.md`). This supplies the
before/after baseline the acceptance criteria asked for.

Finding: the verifier as first landed excluded only the **ticker symbol** from its token
overlap, so any two articles about the same watchlist company shared the company **name**
(`nvidia`, `broadcom`, …) and passed — it caught **≤8/31** known cross-story misassignments.

Calibration applied (this commit, within the anticipated "tune the token filters" scope, no
storage-contract change):
- exclude the subject instrument's own name tokens (`instrument_display_name` +
  `instrument_aliases`) from both sides of the overlap, not just the ticker symbol;
- widen the generic-token stoplist 32 → 99 and drop pure-numeric tokens.

Result: **≤8/31 → 28/31** cross-story misassignments downgraded, with **7/7** genuinely
same-story matches preserved (no shattering). Requiring ≥2 overlapping tokens would reach 31/31
but breaks a correct match (CS-0029, the real Apple/Broadcom deal), so the ≥1 rule is retained.

Residual: 3 cases (`network`/`enterprise`/`cloud` single-token overlaps) are the structural
ceiling of bag-of-words overlap and are not closable by token tuning — tracked as **260716-01**
(pair the token floor with an event-level check). 260715-05 stays **resolved**; the residual is
a narrower, separately-scoped problem.
