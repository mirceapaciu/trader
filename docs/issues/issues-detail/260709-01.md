# 260709-01 High-price tickers are structurally unsizeable; generation produces cards the executor can never trade

## Problem Statement

TradeExecutor sizes positions as `qty = floor(risk_box.max_loss_usd / |entry − stop|)` clamped by
`floor(MAX_POSITION_SIZE / entry)` with integer shares. Under the current configuration
(`MAX_POSITION_SIZE = $1,000`, `THESIS_BUILDER_RISK_MAX_LOSS_USD = 120` in
`.env.thesis-builder.example`, `ATR_STOP_MULT = 1.5`), any instrument whose share price exceeds
$1,000 **or** whose 1.5×ATR20 dollar risk exceeds the max-loss box sizes to 0 shares and is
rejected with `size_below_one_share` — on every card, at any confidence, on any day.

ThesisBuilder has no corresponding check, so it happily creates cards for such instruments. The
result is a structural mismatch: in run `bt_2416cea0` **100% of generated trades were
risk-blocked** because the only ticker dense enough to clear the evidence gate (MU, ~$1,200/share,
ATR20 ≈ $93) is unsizeable twice over — price > position cap, and 1.5·ATR ≈ $139 > $120 risk box.
Every card the pipeline could produce was a card it could never trade, and the LLM budget that
produced those cards was wasted.

## Verified Evidence

- `src/product_components/trade_executor/pipeline.py:125-151` — `size_position` sizing floor and
  clamps; `qty < 1` → rejection.
- `src/product_components/trade_executor/settings.py:136` — `MAX_POSITION_SIZE` default 1000.0.
- `src/product_components/thesis_builder/settings.py:91` — `risk_max_loss_usd` default 150.0;
  `.env.thesis-builder.example` sets `THESIS_BUILDER_RISK_MAX_LOSS_USD=120`.
- `docs/verification-runs/260708-bt_2416cea0515f427681f879f1c363ec3d.md` — both trades
  `risk_blocked` / `size_below_one_share`; measured MU entries $1,196.21 and $1,233.00, stop
  distances ≈ $139.6 / $139.3; qty-by-risk 0 and qty-by-notional 0 at both entries.
- `docs/verification-runs/260708-bt_2373c76aac62411386f96c0771a20f75.md` — same block on the MU
  card (50% of that run's card population).
- ThesisBuilder card-creation path has no tradeability precheck (no price-vs-cap or ATR-vs-risk-box
  comparison anywhere in `src/product_components/thesis_builder/`).

## Expected Behavior

ThesisBuilder applies a deterministic **tradeability precheck** before creating a card, using the
market-context snapshot it already fetches:

1. `current_price ≤ tradeability_max_entry_price` (aligned with TradeExecutor's
   `MAX_POSITION_SIZE`), and
2. `ATR_STOP_MULT · atr_20d ≤ risk_max_loss_usd` (the card's risk box must be able to buy at least
   one share of stop distance).

A candidate failing either check is persisted as a rejected card/window outcome with a
machine-readable reason code (e.g. `untradeable_risk_box`), never published to `signal_queue`, and
visible in monitoring like other rejection reasons. The thresholds are ThesisBuilder configuration
(documented in `thesis-builder/configuration.md`) with defaults that match TradeExecutor's; the
coherence requirement between the two components' values is documented in both configuration
specs. When market context is unavailable for the check, fail closed for the card (consistent with
§3.2 fail-closed policy).

Alternative resolutions — fractional-share support in TradeExecutor, or raising
`MAX_POSITION_SIZE` / the risk box — are product decisions that would supersede this filter; the
filter is the cheapest change that stops producing dead-on-arrival cards and wasting LLM spend on
them. If caps are raised instead, this issue is satisfied when no watchlisted instrument is
structurally unsizeable.

## Acceptance Criteria

- A card candidate for an instrument with `current_price > tradeability_max_entry_price` or
  `ATR_STOP_MULT · atr_20d > risk_max_loss_usd` is rejected with a distinct reason code and not
  published; the rejection is auditable (persisted with the market-context snapshot used).
- A regeneration backtest over a window containing MU-like instruments produces **zero**
  `size_below_one_share` risk blocks originating from structurally unsizeable instruments.
- Instruments passing the precheck are unaffected (no behavior change for sizeable names).
- Defaults are coherent with TradeExecutor's live values, and the coherence rule is documented in
  both components' configuration specs.

## Test Plan

- Unit tests (ThesisBuilder): card-creation with a fake market context where (a) price exceeds the
  cap, (b) ATR risk exceeds the box, (c) both pass — only (c) creates a card; (a)/(b) persist the
  rejection reason code. Missing/stale context → fail closed.
- Unit test: reason code appears in the persisted card/window record and is excluded from
  `signal_queue` publication.
- Backtester regression: regeneration run fixture with a high-price instrument yields no
  `size_below_one_share` blocks and records the generation-side rejections instead.
- Config test: defaults align with `trade_executor` settings defaults (guard against silent drift).
