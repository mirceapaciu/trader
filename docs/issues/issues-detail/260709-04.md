# 260709-04 Confidence gates never bind — measure LLM confidence calibration, then recalibrate or replace them

## Problem Statement

Both trade gates keyed on LLM self-reported confidence are dead configuration as set:
`THESIS_BUILDER_MIN_CONFIDENCE = 0.6` and `TRADE_EXECUTOR_MIN_CONFIDENCE = 0.6`. Across the 704
LLM analyses in the two verified regeneration runs, **zero** were rejected
`below_min_confidence` — gpt-4o-mini's reported confidence clusters at 0.78–0.85 regardless of
evidence quality. The gates therefore filter nothing, while the design treats confidence as
load-bearing: the risk-box policy lowers max loss for "lower-confidence" cards
(thesis-builder behavior §7), strategy policy demands "stronger confidence" for contrarian cards,
and `docs/trading-strategies.md` §6 sizes positions off confidence bands. Nothing in the system
measures whether reported confidence correlates with trade outcomes, so every confidence-derived
behavior is currently built on an unvalidated, likely uncalibrated number.

## Verified Evidence

- `docs/verification-runs/260708-bt_2373c76aac62411386f96c0771a20f75.md` — "0 of 348 analyses
  rejected `below_min_confidence`; both cards landed at 0.783. The gate is uninformative as
  configured."
- `docs/verification-runs/260708-bt_2416cea0515f427681f879f1c363ec3d.md` — "0 of 356 analyses
  rejected below it; both cards at 0.85. `min_confidence = 0.6` still never binds."
- `src/product_components/thesis_builder/settings.py:87` — default 0.6; also
  `contrarian_min_confidence` 0.72 and `trend_follow_min_confidence` 0.68 sit inside the observed
  cluster.
- `src/product_components/trade_executor/settings.py:127` — default 0.6.
- `docs/design/product_components/thesis-builder/behavior.md` §7 — risk box scales with
  confidence; §6 — strategy conflicts resolved by confidence comparisons.

## Expected Behavior

1. **Measure first.** A calibration analysis over persisted analyses/cards and their realized
   outcomes (backtester trades and, later, live trades): bucket analyses by reported confidence
   and compare directional hit rate / trade P&L per bucket. This can run as a verification script
   or a backtester report section; it requires no live trading. Output is persisted/reportable so
   the check can be repeated as samples grow.
2. **Then act on the result:**
   - If confidence discriminates (higher buckets → better outcomes), set the gates at values that
     actually bind (data-derived, e.g. the observed distribution's lower quartile) and document
     the calibration basis in the configuration specs.
   - If it does not discriminate, remove or demote confidence as a gating/sizing input: gates
     become no-ops explicitly (documented), and risk-box scaling by confidence is dropped until a
     calibrated signal exists.
3. Whichever branch, the configuration specs stop presenting 0.6 as a meaningful safety control.

Given current sample sizes (n=1 closed trade), the measurement tooling can land now, but the
recalibration decision is expected to wait for the ≥30-trade holdout sample (after 260709-01/-02/
-03 unblock trade generation). This issue tracks both halves so the dead gate is not forgotten.

## Acceptance Criteria

- A repeatable calibration report exists (script or backtester output) showing outcome metrics per
  confidence bucket over all closed backtest trades, runnable against any completed run/window.
- Gates and confidence-scaled behaviors are either (a) reconfigured to values shown to bind and
  discriminate, or (b) explicitly removed/neutralized, with the decision and evidence recorded in
  this issue and the configuration docs updated to match.
- No component silently keeps a threshold inside the observed always-passing band without a
  documented rationale.

## Test Plan

- Unit tests for the calibration computation: fixture analyses + trades → correct bucketing, hit
  rates, and handling of empty buckets / n too small (report says so instead of emitting noise).
- Unit tests for whichever decision lands: gate at new threshold rejects a fixture analysis below
  it (and the funnel records `below_min_confidence`), or removed gate no longer appears in the
  admission path.
- Re-run the calibration report on a consumed window and confirm outputs match hand-computed
  values for the known trades.
