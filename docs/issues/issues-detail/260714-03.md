# 260714-03 subject_relation=direct is self-reported by the LLM; misclassified sector stories bypass the indirect-evidence gates

## Problem Statement

260714-01 introduced `subject_relation` so indirect news is anchor-gated and magnitude-capped,
but the `direct` label itself is taken from the LLM on trust. A mislabeled `direct` bypasses
the entire indirect machinery: no anchor-evidence requirement, no low-magnitude cap, and it
counts as the direct seed that lets a thesis card form. The old deterministic-ish prompt rule
("articles where the instrument is not named are NOT about it") was removed by 260714-01 and
not replaced with a deterministic post-LLM equivalent.

Observed on card `36db49d9-b3a0-5e20-8ca9-b7ee99f8d367` (NVDA, buy, event_driven, created
2026-07-14 17:09 UTC, `signal_published_at` set — the signal reached the executor queue). Its
three source analyses:

- **8603** "Prediction: Poet Technologies Has 160% Upside…" — correctly `customer_or_peer`,
  magnitude capped to low, anchor check passed legitimately (direct valid analyses were in the
  collecting window minutes earlier). Working as designed.
- **8604** "Applied Optoelectronics Rallies 6%, Lumentum Climbs 5% as Texas Expansion Fuels AI
  Optics Trade" — labeled **`direct`** for NVDA although NVIDIA is never named in headline or
  summary. Entered at magnitude medium, counted as a direct seed.
- **8621** "U.S. trade official says 'very few' Nvidia H200 AI chips have been shipped to
  China" — genuinely direct.

The failure is systematic, not a one-off: of 70 valid `direct` analyses since
`subject_relation` went live, **9 (13%) never name the instrument** in headline+summary
(matched against ticker + `t_instruments.aliases` + `display_name`), e.g. "Reflection inks $1B
compute deal with Nebius" → NVDA, "Apple Stock Hits a Record as the AI Memory Crisis Guts
Cheap Phones" → MU, "Software Stocks Sink as IBM Miss…" → MSFT.

Related operational gap: the 260714-02 alias backfill has not fully landed in production —
BRK.A gained "berkshire hathaway", but GOOGL still lacks "google" and NVO still lacks the
unhyphenated "novo nordisk" (the curated-extras cases). One of the 9 flagged rows ("Google Vs.
Nvidia…" → GOOGL) is that alias gap rather than an LLM error, and the backstop proposed below
matches against the same alias data, so the backfill must be run for the backstop to be
accurate.

## Additional Evidence (2026-07-15)

Card `ffe63506-f02a-5849-ab26-b607fa672344` (NVDA, buy, event_driven, valid, signal published
2026-07-15 10:42 UTC) escalates the severity: all three source analyses are off-instrument.
Analyses 8933 ("Prediction: This Under-the-Radar Dividend Stock Is Going to Skyrocket After
Aug. 4" — a 4.24%-yield stock, not NVDA) and 8947 ("Warren Buffett Bought This New Dow Jones
Stock…") are false `direct`s from Finnhub company-feed teaser articles whose headlines hide the
subject company; 8937 ("Can Penguin Solutions Be the Next 10X Stock?" — PENG) is a correctly
labeled `customer_or_peer` that passed `_has_anchor_evidence` **because false direct 8933 was
already in the collecting window**. False directs therefore don't just bypass the seed
requirement — they mint the anchor evidence that admits indirect articles, so an entire card
can form with zero articles about the instrument. The backstop below closes both paths (an
unverified direct can neither seed nor anchor). The prompt-side companion fix — stop presenting
provider feed tags as ground-truth attribution — is 260715-02.

## Expected Behavior

1. **Deterministic direct-verification backstop.** In `_normalize_analysis_result`, when the
   LLM returns `subject_relation=direct` but the instrument is never named in the article's
   headline+summary — checked with `contains_term` against ticker, `t_instruments.aliases`,
   and `display_name`, i.e. the same matching `_resolve_instrument_pairs` uses — downgrade the
   relation to `customer_or_peer`. The downgraded analysis then inherits the existing indirect
   policy unchanged: anchor-evidence requirement, low-magnitude cap (absent a realized
   surprise), and ineligibility as a card seed.
2. **Provider tags are not proof of directness.** The backstop keys on article text only; a
   Finnhub company-feed tag (`tickers.add(self._ticker)`) must not satisfy it.
3. **Auditability.** A downgrade is recorded (e.g. in `validation_errors` or a dedicated audit
   field/log line) so funnel analysis can distinguish "LLM said direct, backstop downgraded"
   from "LLM said indirect".
4. **Alias backfill executed.** `scripts/audit_watchlist_aliases.py` (260714-02) is run against
   production with curated extras so GOOGL/"google" and NVO/"novo nordisk" match before the
   backstop goes live; the audit reports clean afterwards.
5. **Regeneration parity.** The backstop applies identically in the live path,
   `reprocessor.py`, and `regeneration.py` so sim funnels remain comparable.

## Acceptance Criteria

- Replaying analysis 8604's article for NVDA yields `subject_relation=customer_or_peer`,
  magnitude capped to low, and it cannot serve as a card's direct seed.
- Replaying analysis 8621's article (Nvidia named in headline) remains `direct` and
  byte-identical to today's valid path.
- An article naming the instrument only via a press-name alias (e.g. "Google …" for GOOGL)
  is NOT downgraded once the alias backfill has run.
- The "valid direct but instrument never named" production measurement returns 0 rows for
  analyses created after the backstop deploys (alias-gap residue excluded).
- Downgrades are countable from persisted data without re-running the LLM.
