# 260615-08 Remove Monitoring UI direct database access to ThesisBuilder

## Problem Statement

Monitoring UI currently reads ThesisBuilder-owned telemetry and evidence-window tables directly and bootstraps the ThesisBuilder schema locally. That bypasses the ThesisBuilder component boundary.

## Verified Evidence

- `src/product_components/monitoring_ui/backend/repository.py:109` bootstraps `src/product_components/thesis_builder/db/schema.sql`.
- `src/product_components/monitoring_ui/backend/repository.py:234`, `:256`, `:264`, `:275`, `:280`, `:302`, and `:622` read `thesis_builder.t_news_analyses`, `thesis_builder.t_thesis_cards`, and `thesis_builder.t_evidence_windows`.

## Expected Behavior

Monitoring UI should obtain ThesisBuilder metrics, pending windows, and card telemetry through a ThesisBuilder-owned API or read adapter. Schema bootstrapping and direct SQL into ThesisBuilder tables should be removed from the UI backend.

## Acceptance Criteria

- Monitoring UI backend does not query `thesis_builder` tables directly.
- Monitoring UI backend no longer bootstraps ThesisBuilder schema.
- ThesisBuilder exposes UI-facing telemetry through an owning API or read adapter.
- Monitoring UI integration tests validate the new ThesisBuilder boundary.

## Test Plan

- Run `uv run pytest tests/product_components/monitoring_ui -q`.
- Add integration coverage for UI ThesisBuilder metrics via the replacement API/adapter.
- Add a boundary test that fails if Monitoring UI runtime SQL references `thesis_builder.` directly.
