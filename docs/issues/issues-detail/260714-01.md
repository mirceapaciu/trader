# 260714-01 Binary instrument_is_subject gate mishandles supply-chain read-through articles

## Problem Statement

ThesisBuilder's analysis stage forces the LLM to collapse two different questions into one
boolean: "is the instrument the subject of this article?" and "is this article material to the
instrument?". For indirect but genuinely material news — supply-chain read-throughs, customer/
peer results, sector-moving events — those two questions disagree, and the boolean produces one
of two wrong outcomes:

1. **Rejected as noise.** `instrument_not_subject` is the single largest rejection reason in
   production: 4,372 of 8,313 analyses (53%) between 2026-06-19 and 2026-07-14. Every one of
   those burned a full analysis LLM call, because the recall-biased triage stage passes nearly
   everything through. Material read-throughs rejected this way are lost entirely.
2. **Admitted as a direct catalyst.** When the LLM instead judges the article materially
   relevant and sets `instrument_is_subject=true`, the article enters the evidence window at
   full catalyst weight. 97 of 1,854 valid analyses (5%) never name the instrument in headline
   or summary; their `price_impact_magnitude` distribution is 79 medium / 17 high / 1 null —
   **zero low**. NVDA is the largest recipient (30), consistent with Finnhub's per-symbol
   company-news feed force-tagging supply-chain stories (`tickers.add(self._ticker)`).

The disposition is a coin flip on identical relationship types. Exhibit A: the article "TSMC
seen riding AI boom to fifth straight quarter of record profit" (2026-07-14, article
`cev_ae18b97b…`, tagged NVDA by `finnhub:company:NVDA:XNAS`) was analyzed for two instruments
and got opposite verdicts — **valid** for NVDA (relevance 0.7, confidence 0.85,
`is_market_moving=true`, magnitude medium; now in NVDA's evidence window as if it were a direct
NVDA catalyst) and **rejected** `instrument_not_subject` for Samsung (005930). The article is
moreover a consensus expectations *preview*, not a surprise — even for NVDA it should have
scored low expected magnitude.

## Verified Evidence

- `src/product_components/thesis_builder/service.py:589-596` — triage hard gate
  (`triage_not_subject`); triage prompt is recall-biased by design
  (`llm_client.py:491-499`), so it filters little.
- `src/product_components/thesis_builder/repository.py:832-856` — `_analysis_rejection` hard
  gate: `instrument_not_subject` is checked first and drops the analysis entirely.
- `src/product_components/thesis_builder/llm_client.py:391-406` — analysis prompt instructs
  "articles where the instrument is not named are NOT about it", directly conflicting with the
  materiality judgment the same call must make.
- `src/product_components/news_fetcher/providers.py:196-198` — `FinnhubCompanyNewsProvider`
  unconditionally stamps the queried ticker on every returned article, so read-throughs arrive
  pre-tagged and match via the `ticker_match` path in `_resolve_instrument_pairs`
  (`service.py:571-579`) with no text mention required.
- Production funnel 2026-06-19 → 2026-07-14 (`thesis_builder.t_news_analyses`, 8,313 rows):
  `instrument_not_subject` 4,372 (53%; 2,570 finnhub / 1,802 rss), valid 1,854 (22%),
  `routed_to_analyst` 944, `hold_not_executable` 721, `below_min_relevance` 244,
  `instrument_mismatch` 174. Sim runs (`sim_bt_*` schemas) show the same shape (35–50%).
- Of the 1,854 valid analyses, 97 never name the instrument in headline+summary (matched
  against ticker, `t_instruments.aliases`, and `display_name`); magnitudes 79 medium / 17 high,
  none low. True read-throughs in the sample include Strait of Hormuz → LNG, Samsung results →
  MU, memory-market records → MU, SpaceX data-center deals → GOOGL/AMZN. (Part of the 97 is
  alias gaps — see 260714-02.)

## Expected Behavior

1. **Model the relationship explicitly.** `LlmAnalysisResult` gains
   `subject_relation: direct | supply_chain | customer_or_peer | macro_sector | none` replacing
   the boolean as the source of truth (`instrument_is_subject` remains derivable as
   `relation == direct` for schema compatibility). The analysis prompt defines the enum values
   with examples and drops the "not named ⇒ not about it" rule in favor of classification.
2. **Indirect news supports theses but never seeds them.** `_analysis_rejection` policy:
   - `direct` — current behavior, unchanged.
   - `supply_chain` / `customer_or_peer` — admissible only as supplementary evidence for an
     instrument that already has an active thesis card or direct evidence in the current
     evidence window; otherwise rejected with a new reason code (e.g.
     `indirect_no_anchor_evidence`). Never counts toward seeding a new card.
   - `macro_sector` / `none` — rejected as today (reason code distinguishes them from `none`).
3. **Magnitude cap for indirect relations.** When `subject_relation != direct`,
   `price_impact_magnitude` is capped at `low` unless the article reports a realized surprise
   (actual result deviating from published expectations), not a preview of consensus. The cap
   is applied deterministically post-LLM (not merely requested in the prompt).
4. **Triage unchanged.** The recall-biased triage pass-through stays as is; the fix is in the
   analysis-stage disposition, not upstream. Finnhub provider tagging
   (`tickers.add(self._ticker)`) also stays — it is the recall channel for read-throughs.
5. **Observability.** `subject_relation` is persisted on `t_news_analyses` and surfaced in the
   funnel (rejection reason codes and monitoring UI), so the direct/indirect split is
   measurable in production and in `sim_bt_*` regeneration runs.

## Acceptance Criteria

- The TSMC-preview scenario (indirect + consensus preview, no anchor evidence for the ticker)
  is rejected with the new indirect-specific reason code, for every instrument it is tagged
  with, deterministically.
- An indirect article arriving while the instrument has an active card or direct evidence in
  the window is persisted as valid with `subject_relation` set and magnitude capped at low
  (absent a realized surprise), and contributes to the evidence window without being able to
  satisfy the seed/first-evidence requirement on its own.
- A window containing only indirect evidence never produces a thesis card, regardless of
  count, confidence, or magnitude values returned by the LLM.
- `direct` articles behave byte-identically to today's valid path.
- `t_news_analyses` rows carry `subject_relation`; existing rows remain readable (column
  nullable or defaulted).
- Regeneration/backtest paths (`regeneration.py`, `reprocessor.py`) apply the same policy so
  sim funnels remain comparable to production.

## Test Plan

- Unit (llm_client): response parsing maps each enum value; missing/unknown relation falls back
  safely; `instrument_is_subject` derivation.
- Unit (repository `_analysis_rejection`): matrix of relation × anchor-evidence-present ×
  magnitude → expected reason code or valid; magnitude cap applied for indirect without
  surprise; direct path regression-identical.
- Unit (card/evidence window): indirect-only window never satisfies
  `required_evidence_count` seeding; direct + indirect mix does, with indirect counted as
  supplementary.
- Integration: replay the TSMC article (both DB copies) through ThesisBuilder against a
  watchlist containing NVDA with (a) no NVDA card → rejected indirect; (b) an active NVDA card
  seeded by a direct article → accepted as supplementary evidence with magnitude low.
- Counterfactual (free, per sim-schema workflow): re-score an existing `sim_bt_*` run's
  analyses under the new policy and report the funnel delta before enabling in production.

## Root Cause

The analysis contract used `instrument_is_subject` as a single hard gate for both direct
instrument attribution and material read-through relevance. That made supply-chain/customer-peer
stories either disappear as `instrument_not_subject` or enter the evidence window as full direct
catalysts, depending on how the LLM collapsed the two questions. ThesisBuilder also had no
persisted field for measuring the direct/indirect split.

## Resolution

- Added `subject_relation` (`direct`, `supply_chain`, `customer_or_peer`, `macro_sector`, `none`)
  to the analysis model, LLM prompt/schema/parser, `t_news_analyses`, Monitoring UI analysis
  rows, and ThesisBuilder export contract.
- Kept `instrument_is_subject` as a compatibility boolean derived from `subject_relation ==
  direct`; old cached responses that only set `instrument_is_subject=true` still parse as direct.
- Added deterministic repository policy: `supply_chain` and `customer_or_peer` analyses are
  rejected as `indirect_no_anchor_evidence` unless the instrument already has an active card or
  direct evidence in the current collecting window; `macro_sector` is rejected as
  `macro_sector_not_subject`.
- Added deterministic impact normalization: indirect consensus/preview-style analyses are capped
  to `price_impact_magnitude=low` before persistence.
- Added a card-seeding guard so a satisfied evidence count containing only indirect analyses
  cannot create a thesis card.
