# 260913-01 Include data-source failure details in backtest historical-market-data errors

## Problem Statement

When every instrument in a backtest fails historical-market-data prefetch, the failed run tells the
operator only:

> Historical market data could not be received for the backtest.

The structured details list instruments as `unavailable`, but do not identify which configured data
source was selected or considered, why it was unavailable, or what error the source returned. The
operator therefore cannot distinguish a missing provider configuration or symbol mapping from an
empty provider response, an authentication/rate-limit problem, an IBKR timeout, or another provider
failure without finding and correlating backend logs or private MarketData records.

## Verified Evidence

- The latest Haas backtest, `bt_8a2c1456940d407ab45a60f20672bab1`, ran from
  `2026-09-12 10:00:40 UTC` to `10:02:05 UTC` and finished with
  `error_code=MarketDataUnavailableError`. Its persisted `error_details_json` contains the generic
  message, interval `1m`, and eight instruments (AMD, CRM, GOOGL, META, MSFT, MU, NVDA, and XOM),
  all with only `status="unavailable"`; it contains no source/provider or underlying error.
- `src/product_components/market_data/service.py` catches exceptions from
  `fetch_historical_bars`, records only the exception class as `error_code` in the component-private
  fetch-run record, and returns `None`. `prefetch_historical_bars` converts both that failure and a
  successful zero-bar result into the same public outcome, `"unavailable"`.
- The same prefetch path also emits `"unavailable"` when no provider symbol mapping exists or the
  mapped provider client is not configured, so several operationally distinct causes are
  indistinguishable at the Backtester boundary.
- `src/product_components/backtester/service.py` builds `MarketDataUnavailableError.details` only
  from `(ticker, exchange_code, status)` tuples. The stored run error cannot include information the
  MarketData contract did not return.
- `src/product_components/monitoring_ui/frontend/src/backtester/BacktesterTab.tsx` displays only
  `error_details.message` for this failure, leaving the existing per-instrument details invisible as
  well as incomplete.

## Expected Behavior

A failed all-instrument prefetch should immediately explain that no usable historical data could be
obtained from the available/configured sources and provide enough safe detail for an operator to
choose the next action. The persisted run error and Monitoring UI should identify, at minimum, the
affected instrument, the relevant source/provider, a distinct failure category, and a bounded,
non-secret provider error message when one exists.

The diagnostics should distinguish cases such as:

- no historical-data provider is configured or available;
- no provider-symbol mapping could be resolved;
- the provider returned no bars for the requested interval/window;
- a provider request failed, including its safe exception/error code and message.

This issue improves failure reporting only; it does not require adding provider fallback or changing
which source is selected.

## Acceptance Criteria

- The MarketData-to-Backtester prefetch contract returns a structured, machine-readable outcome for
  each unavailable instrument instead of collapsing every cause to the string `"unavailable"`.
- Each failed outcome identifies the ticker/exchange, attempted or selected provider when known, a
  stable failure category, and a bounded/sanitized error code and message when the provider supplied
  one. It must not expose credentials, tokens, DSNs, request headers, or other secrets.
- A no-provider/no-mapping outcome reports the sources that were considered or why none were
  eligible, without claiming that a provider request was attempted.
- A successful request returning zero bars is distinguishable from a provider exception.
- `MarketDataUnavailableError.error_details_json` preserves these structured outcomes and uses a
  concise operator-facing summary such as "No usable historical market data was available from the
  configured sources" rather than the current context-free sentence.
- The Monitoring UI renders the summary plus actionable source/cause details for a failed run; the
  operator does not need backend-log or database access to identify the failure class.
- Partial prefetch behavior is unchanged: a run may continue when at least one instrument has usable
  data, while unavailable instruments are logged with the richer structured outcome.
- Existing successful backtests and non-market-data failure reporting remain unchanged.

## Implementation Rationale

The prefetch boundary returned only status strings, while `_fetch_historical_bars` caught provider
exceptions and retained only the exception class in a private fetch-run record. By the time the
Backtester handled an all-instrument failure, the selected provider, routing decision, exception
message, and distinction between an empty response and a failed request had already been lost.

The fix introduces a typed `HistoricalBarsPrefetchOutcome` at the MarketData boundary. MarketData
now owns classification and sanitization because it is the component that knows whether routing,
mapping, an empty response, or an exception caused the failure. Backtester serializes those safe
outcomes without reconstructing provider behavior, and the Monitoring UI renders the persisted
structure with a legacy summary-only fallback.

## Changes

- Added per-instrument prefetch outcomes containing canonical instrument identity, status, selected
  provider, ordered considered providers, stable failure category, and optional safe provider error.
- Classified no configured provider, missing symbol mapping, successful empty response, and provider
  exception separately without adding fallback behavior or changing provider selection.
- Added whitespace normalization, request-header and common credential redaction, and 300-character
  bounding for provider error messages; exception-class error codes are bounded to 100 characters.
- Persisted structured outcomes in `MarketDataUnavailableError.error_details_json` with the concise
  operator summary required by this issue. Partial prefetches still continue and now log the stable
  failure category for unavailable instruments.
- Rendered per-instrument provider/cause/error details in the Backtester failure alert, while keeping
  older message-only run payloads safe and readable.
- Updated the MarketData, Backtester, and Monitoring UI behavior specifications at their component
  boundaries.
