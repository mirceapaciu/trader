# 260709-03 Implement already-priced move suppression (close the documented §1.4 known gap)

## Problem Statement

The system's stated edge is post-event drift on multi-day, news-confirmed theses; the design
explicitly cedes the initial jump on fast, clean news and promises to "fail closed instead" of
buying a spent move (`docs/design/overview.md` §1.4, `docs/one-pager.md`). That posture depends on
one guardrail: suppressing cards whose move has already happened. Both design docs flag this
guardrail as a **KNOWN GAP — not implemented**: market context is fetched, passed to the LLM, and
persisted, but no deterministic gate and no prompt instruction suppresses an already-priced move.
A card on a spent spike is emitted as `valid` and trades.

Because the pipeline's confirmation requirements (multi-source evidence + polled ingestion + LLM
analysis) make entry *systematically late by design*, the missing gate converts the intended
drift strategy into late momentum-chasing. The only closed trade across all backtests to date
(CRM long, entered the news day, stopped out −8.66% after an adverse gap) is this failure shape.

## Expected Behavior

Two layers, both auditable:

1. **Deterministic gate (authoritative).** At card-creation time, ThesisBuilder evaluates the
   market-context snapshot against the thesis direction. A configurable rule of the form
   "the instrument has already moved more than `X · atr_20d` (or `Y%`) in the thesis direction
   since the earliest evidence article / over the prior 1-day return" rejects the card with a
   machine-readable reason code (e.g. `already_priced`), persisted with the snapshot that
   triggered it. Thresholds are per-strategy configuration (`event_driven`,
   `sentiment_momentum`) documented in `thesis-builder/configuration.md`. Missing or unusable
   market context follows the existing §3.2 fail-closed policy for strategies that require the
   gate.
2. **Prompt instruction (advisory).** The analysis prompt instructs the LLM to lower
   confidence / prefer `hold` when the provided market context shows the move already realized,
   so the signal quality improves upstream of the gate. The deterministic gate remains the
   enforcement point; the prompt change alone does not satisfy this issue. If the card-synthesis
   pass (260709-06) lands, this advisory layer naturally moves into (or is duplicated in) the
   synthesis prompt, where the full evidence dossier and market context are in view at once.

Documentation: overview §1.4 and thesis-builder behavior §5.1 flip from "KNOWN GAP" to describing
the enforced rule.

## Acceptance Criteria

- A card candidate whose direction-aligned prior move exceeds the configured threshold is
  persisted as rejected with reason `already_priced` (plus the context snapshot) and is never
  published to `signal_queue`.
- A candidate below the threshold is unaffected.
- Strategies requiring the gate fail closed when context is missing/stale; the rejection reason
  distinguishes "context unavailable" from "already priced".
- The thresholds are environment-driven, documented, and surfaced like other ThesisBuilder
  config in the monitoring UI config panel.
- Overview §1.4 and behavior §5.1 no longer describe the gap as open.
- A regeneration backtest over a consumed window shows the gate firing on at least the known
  spent-spike cases without eliminating the non-spent population (spot-check via funnel counts).

## Test Plan

- Unit tests: gate evaluation across (direction, prior-move, threshold) combinations — buy after
  +2·ATR run-up rejected; buy after flat context accepted; sell symmetric; boundary at exactly
  the threshold; missing context → fail-closed reason for gated strategies.
- Unit test: rejected candidate persists reason code + snapshot JSON; no review row; no signal.
- Prompt test: `_build_prompt` includes the already-priced instruction when context is present.
- Integration test: end-to-end news consume with a fake MarketData client returning an
  overextended snapshot → analysis persisted, no card published; with a neutral snapshot → card
  published as before.

## Resolution

Root cause: ThesisBuilder fetched and persisted market context, but card creation only applied
evidence freshness and analysis-quality gates. There was no deterministic direction-aligned price
move check, and the full-analysis prompt did not tell the LLM to treat already-realized moves as
spent.

Implemented on 2026-07-09:

- Added a deterministic already-priced gate at thesis-card creation for `event_driven` and
  `sentiment_momentum` cards.
- The gate rejects candidates when direction-aligned 1-day return exceeds the configured strategy
  threshold, or direction-aligned price move exceeds the configured ATR-20 multiple.
- Missing, stale, or otherwise unusable market context fails closed with
  `rejection_reason_code=market_context_unavailable` for gated strategies.
- Rejected candidates are persisted as non-executable audit cards with the market-context snapshot;
  the existing valid-card signal loader prevents review writes and `signal_queue` publication.
- Added ThesisBuilder-owned env settings for per-strategy ATR/return thresholds and included them
  in regeneration config snapshots.
- Added an advisory already-priced prompt instruction while keeping deterministic gate enforcement
  authoritative.
- Surfaced the thresholds read-only in Monitoring UI via `/api/thesis-builder/config` and a
  ThesisBuilder tab panel.
- Updated overview, ThesisBuilder behavior, and ThesisBuilder configuration docs.
