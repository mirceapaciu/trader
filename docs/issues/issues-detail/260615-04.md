# 260615-04 Remove MarketData direct database access to Shared contracts

## Problem Statement

MarketData currently reads the shared watchlist directly and writes provider-usage rows directly into `shared.t_api_usage`. That bypasses the shared component boundary even though the MarketData design now documents shared-contract access.

## Verified Evidence

- `src/product_components/market_data/storage_adapter.py:45` reads active instruments from `shared.<watchlist_table>`.
- `src/product_components/market_data/storage_adapter.py:349` inserts directly into `shared.t_api_usage`.

## Expected Behavior

MarketData should retrieve watched instruments through a shared Instrument Registry API or adapter and should record provider usage through a shared usage API or adapter. Direct SQL against shared tables should not remain in MarketData storage code.

## Acceptance Criteria

- MarketData runtime does not query the shared watchlist table directly.
- MarketData does not insert API-usage rows directly into `shared.t_api_usage`.
- Shared watchlist and usage interactions are routed through shared-owned APIs or adapters.
- Boundary tests fail if MarketData runtime SQL references `shared.` directly.

## Test Plan

- Run `uv run pytest tests/product_components/market_data -q`.
- Add focused tests for shared contract adapters used by MarketData.

## Root Cause

MarketData embedded shared-contract SQL inside its own PostgreSQL storage adapter for both watchlist reads and API-usage writes. That made the component depend on the physical `shared` schema layout instead of consuming the shared-owned contract surfaces already used elsewhere in the repo.

## Resolution

- Added a shared-owned `PostgresSharedApiUsageWriter` adapter for `shared.t_api_usage` appends.
- Updated `PostgresMarketDataStorageAdapter` to consume injected shared adapters instead of issuing direct SQL against shared tables.
- Rewired MarketData construction in ThesisBuilder bootstrap to inject the shared Instrument Registry and shared API usage writer.
- Added boundary coverage to fail if MarketData runtime files reference shared watchlist or API-usage tables directly.
- Added focused unit tests for the shared API usage adapter and MarketData delegation behavior.

## Test Evidence

- `uv run pytest tests/product_components/market_data -q` passed with 17 tests.
- `uv run pytest tests/product_components/thesis_builder/test_shared_adapters.py -q` passed with 4 tests.

## Remaining Risks

- Other components still have separate shared-boundary cleanup work tracked in their own issues; this fix only removes the MarketData runtime dependency on shared physical tables.
