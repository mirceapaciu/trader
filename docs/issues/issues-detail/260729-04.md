# 260729-04 Complete the Monitoring UI taxonomy decision workflow

## Parent Issue

`260728-01` — Add operator workflow for accepting controlled event-identity values.

## Problem Statement

Monitoring UI currently lists taxonomy gaps but provides no selection drawer, canonical
value lookup, map/accept/reject forms, confirmation, command polling, conflict handling,
or backfill feedback. API request types exist, but users still cannot complete the
workflow safely from the UI.

## Verified Evidence

- `TaxonomyGapsPanel` renders a read-only table.
- The frontend API has a taxonomy-decision request function.
- No component calls the mutation function.
- No command-status polling API or UI state exists.

## Expected Behavior

### Gap list

- Filter by dimension and status.
- Sort by occurrence count and last seen.
- Preserve filters and selection during refresh.
- Show open, command pending, mapped, accepted, rejected, and failed states.

### Detail drawer

- Selecting a row opens a keyboard-accessible drawer.
- Show proposal, raw value, dimension, family scope, occurrence history, representative
  analyses/headlines, and previous decision state.
- Link representative analysis IDs to analysis detail.
- Load valid canonical targets for the selected dimension and family scope.

### Decision forms

- **Map to existing:** searchable scoped canonical selector and required rationale.
- **Accept as new:** normalized canonical preview, display name, description, applicable
  family scope/discriminators, and required rationale.
- **Reject:** required rationale and optional controlled rejection reason.
- All actions require an explicit confirmation dialog.

### Submission and feedback

- Submit an idempotent command using authenticated request context.
- Disable duplicate submission while pending.
- Poll command status until completed or failed.
- Show the resulting taxonomy revision and backfill progress.
- On conflict, reload the gap and explain that another operator decided it.
- Do not optimistically show completion.
- Errors are actionable and preserve entered form values where safe.

## Acceptance Criteria

- An authorized user can map, accept, and reject from the Taxonomy Gaps panel.
- Canonical selectors are dimension- and family-scope-aware.
- Rationale and confirmation are mandatory.
- Pending state survives ordinary query refreshes.
- Command polling stops at a terminal state and does not leak timers.
- Conflict, authorization, validation, command failure, and backfill failure are
  distinguishable.
- Success shows the committed integer taxonomy revision.
- Backfill status and counts are visible.
- Keyboard navigation, focus return, form labels, validation summaries, and dialog
  semantics are accessible.
- The browser never supplies a trusted actor string.
- No direct database mutation is added to Monitoring UI.

## Resolution

The Taxonomy Gaps panel now provides dimension/status filters, deterministic sorting,
a keyboard-accessible detail drawer, representative-analysis links, and
dimension/family-scoped canonical lookup. Operators can map to an existing value,
accept a new canonical value, or reject a proposal. Every action requires a rationale
and confirmation.

Submission uses a stable idempotency key and never supplies an actor from the browser.
The panel preserves form state on safe retries, polls accepted/running commands, stops
after command and backfill reach terminal states, distinguishes authorization,
conflict, validation, command, and backfill failures, and displays the committed
taxonomy revision and bounded backfill counters.

Verification:

- Focused component tests passed (`17 passed`).
- The production frontend build passed (`746 modules transformed`).
- The running backend listed the seeded open proposal, accepted an authenticated
  `accept_new` action with `202`, exposed completed command/backfill status, and then
  returned the new canonical value from the scoped-values endpoint at revision `2`.
- The same accepted value resolved in a subsequent in-memory runtime snapshot without
  restarting or deploying ThesisBuilder.
- The submitted `identity_discriminators` were persisted exactly, and the browser/API
  field-name mismatch found during verification was corrected.
