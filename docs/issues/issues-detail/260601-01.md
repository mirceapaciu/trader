# 260601-01 Add simulation-first filter quality infrastructure

## Problem Statement

The previous NewsFetcher flow only persisted accepted articles and dropped non-accepted candidates too early. That made it impossible to simulate a new filtering configuration against the already ingested news corpus and compare the new outcome against production filtering behavior.

## Verified Evidence

- `src/product_components/news_fetcher/source_adapter.py` previously removed non-relevant articles before the ingestion engine saw them.
- `src/product_components/news_fetcher/storage_adapter.py` previously persisted only accepted articles plus publication obligations.
- The new Filter Quality Evaluator requirement needs a 30-day stored corpus and isolated simulation results that do not affect the production NewsFetcher pipeline.

## Expected Behavior

The system should persist a 30-day normalized input corpus, record production filter outcomes per article, and allow the Filter Quality Evaluator to run isolated simulation passes over that stored corpus. Simulation results must be stored separately from production results and must not affect checkpoints, accepted-news publication, or other production pipeline behavior.

## Acceptance Criteria

- `news_fetcher.t_input_news_articles` stores the normalized candidate corpus for the last 30 days.
- `news_fetcher.t_news_articles` remains the accepted durable subset.
- `news_fetcher.t_news_filter_runs` stores production and simulation run metadata.
- `news_fetcher.t_news_filter_results` stores one filter decision per article per run.
- Production NewsFetcher writes baseline filter results automatically.
- Simulation runs do not mutate production accepted rows, checkpoints, or queue publication.
- Relevant unit and integration tests pass.

## Resolution

In progress.

Implemented so far:
- Extended the ingestion contract to preserve all structurally valid normalized candidates.
- Added explicit production filter-result handling in the ingestion engine.
- Added NewsFetcher persistence for input corpus rows, production filter runs, and production filter results.
- Added focused unit and integration coverage for the new production baseline persistence path.

Remaining work:
- Implement the Filter Quality Evaluator simulation runner and evaluator-owned assessment tables.
- Complete the end-to-end simulation and recommendation workflow.
