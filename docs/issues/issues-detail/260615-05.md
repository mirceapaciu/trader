# 260615-05 Remove Filter Quality Evaluator direct database access to NewsFetcher

## Problem Statement

Filter Quality Evaluator currently reads NewsFetcher corpus and filter-run tables directly, writes simulation rows directly into NewsFetcher tables, bootstraps NewsFetcher schema locally, and still defines a cross-schema foreign key into `news_fetcher`. That breaks the owning-component database boundary.

## Verified Evidence

- `src/product_components/filter_quality_evaluator/repository.py:35` bootstraps `src/product_components/news_fetcher/db/schema.sql`.
- `src/product_components/filter_quality_evaluator/repository.py:55` reads `news_fetcher.t_input_news_articles`.
- `src/product_components/filter_quality_evaluator/repository.py:110` and `:142` read `news_fetcher.t_news_filter_runs`.
- `src/product_components/filter_quality_evaluator/repository.py:162` inserts into `news_fetcher.t_news_filter_runs`.
- `src/product_components/filter_quality_evaluator/repository.py:176` inserts into `news_fetcher.t_news_filter_results`.
- `src/product_components/filter_quality_evaluator/repository.py:325` and `:354` read `news_fetcher.t_news_filter_results`.
- `src/product_components/filter_quality_evaluator/db/schema.sql:133` defines `REFERENCES news_fetcher.t_input_news_articles(id)`.

## Expected Behavior

Filter Quality Evaluator should consume NewsFetcher-owned evaluation datasets through a NewsFetcher API or export surface. Simulation writes, dataset access, and schema lifecycle must remain owned by NewsFetcher instead of being performed by Filter Quality Evaluator through direct SQL.

## Acceptance Criteria

- Filter Quality Evaluator runtime does not query or write `news_fetcher` tables directly.
- Filter Quality Evaluator no longer bootstraps NewsFetcher schema.
- `filter_quality_evaluator` schema does not declare foreign keys into `news_fetcher`.
- NewsFetcher exposes the evaluator dataset and simulation contract through an owning API/export surface.
- Integration coverage proves the evaluator still works through the new boundary.

## Test Plan

- Run `uv run pytest tests/product_components/filter_quality_evaluator -q`.
- Run `uv run pytest -m integration tests/integration/test_news_fetcher_integration.py tests/integration/test_thesis_builder_integration.py`.
- Add a boundary test that fails if Filter Quality Evaluator SQL references `news_fetcher.` directly.
