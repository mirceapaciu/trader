# 260626-01 Repo-wide pytest collection failure due to duplicate test basenames and missing __init__.py

## Problem Statement

Running `uv run pytest` from the repo root fails at collection with a module import conflict. Multiple test directories share identical filenames (`test_boundary.py`, `test_main.py`, `test_service.py`, `test_settings.py`) and none of the component-level test directories contain an `__init__.py`. Under pytest's default `prepend` import mode, the first collected module under a given basename wins and subsequent files with the same name are silently shadowed or raise a collection error. The workaround `uv run pytest --import-mode=importlib` passes, but it is not the configured default.

## Verified Evidence

- `tests/__init__.py` and `tests/integration/__init__.py` exist, but none of the component-level directories under `tests/product_components/` or `tests/core_components/` have `__init__.py`.
- Duplicate basenames confirmed across component dirs:
  - `tests/product_components/market_data/test_boundary.py`
  - `tests/product_components/news_fetcher/test_boundary.py`
  - `tests/product_components/thesis_builder/test_boundary.py`
  - `tests/product_components/news_fetcher/test_main.py`
  - `tests/product_components/thesis_builder/test_main.py`
  - `tests/product_components/news_fetcher/test_service.py`
  - `tests/product_components/thesis_builder/test_service.py`
  - `tests/product_components/monitoring_ui/test_settings.py`
  - `tests/product_components/thesis_builder/test_settings.py`
- `pyproject.toml` sets `pythonpath = ["."]` but does not set `addopts = --import-mode=importlib`.

## Expected Behavior

`uv run pytest` (no extra flags) should collect and run all tests without collision.

## Acceptance Criteria

- `uv run pytest` passes collection with no `--import-mode` flag required.
- Chosen fix is one of:
  - Add `addopts = --import-mode=importlib` to `[tool.pytest.ini_options]` in `pyproject.toml`, **or**
  - Add `__init__.py` to every component-level test directory so pytest treats them as packages under a unique namespace.
- No test is silently skipped due to basename shadowing after the fix.
- `CLAUDE.md` command examples remain accurate (no flag additions needed in the documented `uv run pytest` invocations, or they are updated to match).

## Test Plan

- Run `uv run pytest` from repo root and confirm zero collection errors.
- Run `uv run pytest tests/product_components/news_fetcher -q` and `uv run pytest tests/product_components/thesis_builder -q` in the same session and confirm both `test_service.py` files are collected separately.

## Root Cause

pytest's default `prepend` import mode inserts the test file's parent directory at the front of `sys.path`. When two files share a basename in sibling directories and neither directory is a package (no `__init__.py`), the second collected file resolves to the already-imported module from the first directory, causing a collision.
