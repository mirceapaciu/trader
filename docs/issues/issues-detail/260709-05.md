# 260709-05 docs/trading-strategies.md describes a system that does not exist — align it with the implementation

## Problem Statement

`docs/trading-strategies.md` presents itself as the description of "the trading strategies used by
the news-based trading bot", but it diverges from the implemented system on essentially every
operative detail:

- **Exits:** the doc specifies +3% take-profit / −1.5% stop / 4-hour time stop (momentum) and
  per-event exit tables. The implementation uses a 1.5×ATR stop, 2R take-profit, and a
  time-horizon exit of up to 5 days (`swing_1d_5d`) — a completely different trade geometry.
- **Strategies:** three of the five documented strategies (contrarian reversal, sector rotation,
  trend follow) are not implemented — the LLM prompt scopes v1 to `event_driven` and
  `sentiment_momentum` and instructs that unsupported strategies "must still be labeled"; no
  deterministic entry conditions for the other three exist anywhere.
- **Signal logic:** the recency-weighted sentiment aggregation (§1), the 5-articles-in-2-hours
  contrarian trigger (§3), the `SECTOR_PEERS` config (§4), and the strategy conflict-resolution
  matrix (§5) have no implementation.
- **Sizing:** §6 sizes positions off confidence bands ($1,000/$500/none); the executor sizes off
  the card's risk box and ATR stop distance (`trade_executor/pipeline.py::size_position`).

Anyone evaluating or tuning "the strategies" from this doc is evaluating a fiction. This is not
hypothetical: the doc's targets (§9: 3–5 momentum trades/day, 55–60% win rate, 1–4 hour holds)
describe an intraday system, while the implemented product deliberately targets multi-day swing
theses (`docs/design/overview.md` §1.4) — the two documents contradict each other on the system's
basic regime.

## Verified Evidence

- `docs/trading-strategies.md` §§1, 3, 4, 5, 6, 9 as summarized above.
- `src/product_components/thesis_builder/llm_client.py:215-220` — `strategy_scope_v1:
  ["event_driven", "sentiment_momentum"]`; other strategies label-only.
- `src/product_components/trade_executor/settings.py:129-130` — `ATR_STOP_MULT=1.5`,
  `TAKE_PROFIT_R=2.0`; `pipeline.py:100-151` — ATR bracket construction and risk-box sizing.
- `docs/design/product_components/trade-executor/behavior.md` §§3.4–3.5 — the authoritative
  (and implemented) exit/sizing spec.
- `docs/design/overview.md` §12 links `trading-strategies.md` as the "Trading strategies"
  reference without any staleness marker.

## Expected Behavior

`docs/trading-strategies.md` is either rewritten or explicitly demoted so that documentation and
implementation agree:

1. **Rewrite (preferred):** the doc describes the strategies as actually implemented — the two
   live strategies, evidence-window signal generation, ATR-bracket/R-multiple exits, risk-box
   sizing, and the §1.4 swing regime — and moves unimplemented strategies into a clearly separated
   "roadmap / not implemented" section with their preconditions (e.g. contrarian requires the
   market-context checks of thesis-builder behavior §3.2).
2. **Or demote:** a prominent banner states the doc is an aspirational design sketch that does not
   describe current behavior, pointing to the component behavior specs as authoritative.

Either way, an implementation-status table (strategy → implemented / label-only / roadmap) exists,
and performance targets that describe the intraday regime are removed or reframed for the swing
regime.

## Acceptance Criteria

- No exit rule, sizing rule, entry threshold, or strategy list in `docs/trading-strategies.md`
  contradicts the implemented behavior specs (`trade-executor/behavior.md`,
  `thesis-builder/behavior.md`) or the code defaults.
- Unimplemented strategies are unambiguously marked as such, in one place, with what would be
  required to enable them.
- `docs/design/overview.md` §12 reference reflects the doc's corrected status.
- A reader can determine the system's actual trade geometry (stop, target, horizon, size) from
  the doc without reading the code.

## Resolution

Status: resolved.

Root cause: `docs/trading-strategies.md` was an older intraday strategy sketch but was still linked
as if it described the runtime system.

Steps taken:
- Rewrote `docs/trading-strategies.md` as a current-runtime contract for the implemented swing
  system.
- Added an implementation-status table showing `event_driven` and `sentiment_momentum` as the v1
  implemented strategies, with `sector_rotation`, `contrarian_reversal`, and `trend_follow`
  clearly marked label-only / roadmap.
- Replaced fixed intraday exits and confidence-band sizing with the implemented ATR/R-multiple
  bracket and risk-box sizing rules.
- Updated `docs/design/overview.md` so the reference calls the file the current runtime
  trading-strategy contract.

Verification:
- Grepped docs and README for stale `trading-strategies.md` references and obsolete intraday claims.
- Cross-checked the revised quantitative defaults against `ATR_STOP_MULT=1.5`,
  `TAKE_PROFIT_R=2.0`, and the v1 `strategy_scope_v1` prompt values.

Remaining risks:
- Historical design-review and issue documents still quote the stale behavior as evidence; those
  references are intentionally preserved as historical context.
