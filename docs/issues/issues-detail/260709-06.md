# 260709-06 Add a strong-model card-synthesis pass at evidence-window satisfaction (tier 2)

## Problem Statement

The pipeline's highest-stakes decision — "do these 3+ articles plus market context justify a
trade?" — is currently made by no model at all. The only LLM tier runs per (article × instrument)
with gpt-4o-mini; when an evidence window is satisfied, the thesis card is assembled
mechanically: card confidence is the plain average of per-article confidences
(`thesis_builder/repository.py:330`), evidence bullets are concatenated from per-article output,
and no step ever reasons over the evidence set as a whole. Consequences:

- Three mildly-bullish opinion-adjacent analyses aggregate into a card exactly like three strong
  independent catalysts — there is no holistic coherence check.
- The nuanced judgments the product posture depends on (is the move already priced? do the
  articles corroborate or merely repeat each other? does market context contradict the thesis?)
  are either absent or delegated to the weakest model at the wrong granularity (per-article).
- Card confidence inherits gpt-4o-mini's uncalibrated per-article confidence (see 260709-04).

The volume/stakes profile makes a strong model affordable precisely here: satisfied windows are
projected at ~1–2/day (vs ~30 full analyses/day), so a frontier-class synthesis call costs a few
thousand tokens per day — negligible against the ≤100 EUR/month budget — while per-article
analysis stays on the cheap model.

## Verified Evidence

  `_update_window_and_maybe_create_card`: deterministic assembly; line 330 averages confidence;

  synthesis with market context could plausibly have refused.
- `docs/design/product_components/thesis-builder/behavior.md` §5 — card creation "selects the
  best evidence set" and generates fields; no synthesis/reasoning step is specified or
  implemented.
- Related issues: 260709-03 (already-priced gate — the deterministic gate stays authoritative;
  the synthesis pass is the natural home for its advisory/prompt layer), 260709-04 (confidence
  calibration — synthesis-produced confidence is a new candidate signal that must enter the same
  calibration measurement), 260709-02 (tiers 0/1 upstream of full analysis).

## Expected Behavior

When an evidence window reaches satisfaction (after all deterministic gates: evidence count,
freshness, tradeability per 260709-01, already-priced per 260709-03), ThesisBuilder makes one
**card-synthesis LLM call** with a stronger model before creating the card:

1. **Input:** the full evidence dossier — all window analyses with their article snapshots,
   the persisted market-context snapshot, candidate strategy/direction/horizon, and the
   deterministic gate results.
2. **Structured verdict:** `approve | reject`, synthesis confidence, thesis summary, selected
   evidence bullets, risk-box rationale (stop/invalidation conditions in deterministic terms),
   and machine-validatable reasoning fields — same fail-closed schema validation as the tier-1
   contract (invalid output ⇒ no executable card).
3. **On approve:** the card is created using the synthesis output for confidence, evidence
   bullets, reasoning, and risk-box text (per-article analyses remain persisted unchanged);
   the synthesis request/response is persisted on the card for audit.
4. **On reject:** the window is closed `rejected` with reason code `synthesis_rejected` and the
   verdict persisted; no card, no review row, no signal.
5. **On LLM failure** (after retries): **fail closed** — no executable card
   (`synthesis_unavailable`), consistent with the product constraint. A config flag may allow
   falling back to the current mechanical assembly, but fail-closed is the default.
6. **Configuration:** `THESIS_BUILDER_SYNTHESIS_MODEL`, enable flag (disabled ⇒ current
   mechanical assembly, preserving today's behavior), max output tokens, timeout/retries;
   documented in `thesis-builder/configuration.md`. Synthesis tokens count against budgets and
   API usage accounting.
7. **Live parity:** regeneration backtests run the same synthesis step with the same
   configuration, and the LLM analysis cache (260708-02) extends to synthesis calls so repeated
   backtests over the same windows are free.

Sequencing note: this issue should land **after** 260709-01/-02/-03 unblock trade generation and
a ≥30-trade baseline exists on a holdout window; otherwise the quality effect of the synthesis
pass is unmeasurable. Enablement is an A/B against that baseline (synthesis on vs off over the
same window), judged on card precision and edge, not intuition.

## Acceptance Criteria

- With synthesis enabled, every executable card carries a persisted synthesis verdict from the
  configured model; cards rejected by synthesis appear in the funnel with `synthesis_rejected`.
- Synthesis LLM failure produces no executable card by default; the fallback flag, when set,
  reproduces the pre-synthesis mechanical assembly.
- With synthesis disabled, behavior is byte-for-byte the current mechanical assembly (regression
  guard).
- Card confidence equals synthesis confidence when enabled; per-article confidences remain
  persisted and the calibration report (260709-04) can bucket by either.
- A regeneration backtest with synthesis enabled runs end-to-end, hits the synthesis cache on a
  repeat run (zero new synthesis tokens), and its funnel counts reconcile
  (windows satisfied → synthesized → approved/rejected → cards).
- Token accounting shows synthesis spend separately from per-article analysis spend.

## Test Plan

- Unit tests (fake synthesis client):
  - Approve verdict → card created with synthesis confidence/bullets/rationale; verdict persisted.
  - Reject verdict → window `rejected` / `synthesis_rejected`, no card, no review row, no signal.
  - Malformed/schema-invalid synthesis output → fail closed, distinct reason code.
  - Client failure after retries → `synthesis_unavailable`, no card; with fallback flag →
    mechanical assembly result identical to synthesis-disabled path.
  - Disabled flag → fake synthesis client asserts zero invocations; card equals current assembly.
- Idempotency test: redelivery of the triggering news message does not produce a second synthesis
  call or duplicate card (existing idempotency keys extended to cover the synthesis step).
- Budget/accounting test: synthesis tokens debited and attributed to the synthesis category.
- Backtester integration test: regeneration run with a fake synthesis client — funnel counts
  reconcile; second run over the same window served from cache.
- Holdout A/B (manual, post-baseline): same window with synthesis on/off; compare card counts,
  rejection reasons, and closed-trade outcomes; record results in a verification-run report.

## Resolution

Status: resolved.

Root cause: card creation mechanically averaged per-article outputs after evidence-window
satisfaction, so no model reasoned over the full dossier before a tradeable card was created.

Steps taken:
- Added `LlmSynthesisResult`, strict synthesis parsing, an OpenAI synthesis response schema, and a
  `ThesisCardSynthesizer` that uses the same budget discipline as analysis/triage calls.
- Added ThesisBuilder synthesis settings:
  `THESIS_BUILDER_SYNTHESIS_ENABLED`, `THESIS_BUILDER_SYNTHESIS_MODEL`,
  `THESIS_BUILDER_SYNTHESIS_MAX_OUTPUT_TOKENS`, and
  `THESIS_BUILDER_SYNTHESIS_FALLBACK_TO_MECHANICAL`.
- Wired synthesis into evidence-window satisfaction after deterministic freshness and
  already-priced gates. Approve verdicts replace mechanical confidence/evidence/risk text; reject,
  invalid, or unavailable verdicts fail closed by default and mark the window rejected.
- Added `thesis_builder.t_card_synthesis_verdicts` to persist approve/reject/invalid/unavailable
  synthesis outcomes for audit.
- Preserved disabled-by-default behavior so the current mechanical assembly remains the default
  unless synthesis is explicitly enabled.
- Wired Backtester regeneration snapshots and runner thresholds through the synthesis settings, and
  extended the existing Backtester LLM cache wrapper to cache synthesis prompts as well as
  per-article analysis prompts.
- Updated ThesisBuilder behavior/configuration/data-model docs and the Backtester cache data-model
  doc.

Verification:
- Added parser tests for approve, reject, and malformed synthesis outputs.
- Added settings tests for synthesis defaults and env overrides.
- Added Backtester cache coverage for synthesis prompt hits returning zero estimated tokens.
- Ran focused ThesisBuilder and Backtester test slices covering synthesis parser/settings/service,
  regeneration snapshot/cache behavior, and the confidence-calibration report.

Remaining risks:
- Synthesis is disabled by default. It should be enabled only for a measured A/B over the same
  holdout window after enough baseline closed trades exist.
- The first live or regeneration A/B should record card counts, synthesis rejection reasons,
  token usage, cache hits, and closed-trade outcomes in a verification-run report.
