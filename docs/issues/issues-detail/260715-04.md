# 260715-04 Anchor-evidence gate runs before story assignment and is key-scoped; a `new_story` indirect analysis seeds an anchor-less window

> **Scope note (2026-07-15 revision).** This issue was originally filed with a broader framing
> that held up analysis 9176 as the correct/control case. Deeper verification showed 9176 is
> itself a defect — the more severe one, with a published signal — caused by a *different* root
> cause (unverified LLM story assignment). That defect is now **260715-05**; this issue is
> narrowed to the deterministic gate-ordering bug only. The two fixes are independent: neither
> subsumes the other. Do not treat 9176-style outcomes as validation targets for this issue.

## Problem Statement

260714-01 established the invariant that indirect evidence (`subject_relation` of
`supply_chain` or `customer_or_peer`) is supplementary only:

> Indirect evidence is supplementary only. It is valid only when the instrument already has an
> active thesis card or direct evidence **in the current collecting window**, and a window
> containing only indirect evidence never satisfies the seed requirement.
> — `docs/design/product_components/thesis-builder/behavior.md:191`

With `THESIS_BUILDER_STORY_SCOPING_ENABLED=true` (260715-01) the two halves of that invariant
are evaluated against **different windows**:

- `_has_anchor_evidence` (`repository.py:1310`) is **key-scoped**: it asks whether *any*
  collecting window for `(ticker, exchange_code, strategy, direction)` contains a valid direct
  analysis. It runs at `repository.py:178`, before the analysis row is inserted.
- The story-assignment step (`repository.py:602-690`) is **story-scoped** and runs later,
  inside `_update_window_and_maybe_create_card`. It may return `new_story` and seed a
  brand-new window.

Nothing reconciles the two. When the anchor lives in window A and story assignment routes the
analysis to a new window B, the admitted indirect analysis lands in a window that contains no
direct evidence at all — exactly the state the gate exists to prevent. Any live story for the
instrument acts as a free admission ticket for indirect evidence about an unrelated story.

The result is a quarantined but polluted state: a `collecting` window whose only member is
indirect evidence that would have been rejected `indirect_no_anchor_evidence` had no unrelated
story been live at the time.

The story-assignment LLM was correct — Nebius is not the Nokia story. But the only candidate
window, the one whose direct evidence justified admission, was rejected as the destination, and
window 2460 was seeded with the indirect analysis alone. Both steps behaved as individually
specified; their composition violates the invariant.

Corroborating state at admission time: no NVDA card satisfied the `active_card_sql` branch —
`ffe63506-f02a-5849-ab26-b607fa672344` expired 16:42:35 UTC (6 minutes before) and
`e3ba0bbe-7a84-56ed-bce7-5afe50f574cc` was created 16:48:59 UTC (22 seconds after). Window 2456
was the only anchor.

**Blast radius.** Contained today but not zero. Window 2460 cannot mint a card on its own: the
seed guard at `repository.py:439` requires a direct analysis among the selected evidence, and
`_has_anchor_evidence`'s `direct_window_sql` requires `subject_relation='direct'`, so 2460 also
cannot anchor further indirect evidence. Escalation requires a second, independent failure — a
*direct* analysis misassigned into window 2460 by the story LLM (the 260715-05 defect class);
then the Nebius analysis counts toward `required_evidence_count` and its bullet enters a
published card. Today the damage is monitoring inflation (`is_market_moving=true` on an article
not about the instrument) and dead collecting windows.

**Incidence.** Unmeasured. Requires a query over `t_story_assignments` for indirect analyses
with `chosen_target='new_story'` whose admission depended on the window branch of
`_has_anchor_evidence` rather than the active-card branch. Baseline measurement is part of the
work.

## Expected Behavior

1. **The anchor and the destination window must be the same window.** The gate must be
   evaluated against the window the analysis actually lands in, not against any window sharing
   its key. Concretely: when story scoping is enabled, resolve the story assignment *before*
   the anchor decision, then require the anchor in the chosen target — an active unexpired card
   for the assigned story, or direct evidence in the assigned window.
2. **`new_story` + indirect ⇒ rejected.** An indirect analysis assigned to a new story has no
   anchor by construction and must be persisted
   `rejection_reason_code='indirect_no_anchor_evidence'` with no window seeded. Windows
   containing only indirect evidence must never be created.
3. **The active-card branch stays story-aware.** An unexpired card is a valid anchor only when
   story assignment resolves to `card:<id>` for that card, not merely because some card for the
   ticker is alive. A live card for story X must not anchor indirect evidence about story Y.
4. **Story-scoping-disabled behavior is unchanged.** With
   `THESIS_BUILDER_STORY_SCOPING_ENABLED=false` there is one collecting window per key,
   key-scope and story-scope coincide, and today's semantics are preserved.
5. **Fail-open path stays consistent.** The documented fallback (`assignment_source='fallback'`
   → oldest collecting window for the key, or seed new) must route through the same gate: if
   the fallback would seed a new window, an indirect analysis is rejected rather than seeded
   alone.
6. **Ordering cost is acknowledged.** Moving assignment before the gate means rejected indirect
   analyses now pay a story-assignment LLM call they previously skipped (~460-500 tokens on
   `gpt-4o-mini`). The candidate set is already empty-checked, so the cost applies only where
   candidates exist. Alternative — keep the key-scoped gate first as a cheap precheck, then
   re-verify after assignment — is acceptable if the post-assignment check is authoritative.
7. **Out of scope.** Whether an article assigned `window:<id>` actually belongs to that
   window's story is **260715-05** (story-coherence verification). Under this issue alone, an
   indirect analysis assigned to a window containing valid direct evidence is admitted; the
   assignment's correctness is 260715-05's responsibility.
8. **Doc correction (drive-by).** `behavior.md:179` states that 260714-03 and 260715-02 are
   "specified ahead of implementation … as of 2026-07-15 neither is implemented". Both are
   resolved and firing in production (analysis 9172 carries the downgrade audit string). That
   paragraph is stale and should be removed as part of this change.

## Acceptance Criteria

- Replaying the 2460 scenario (window 2456 collecting with direct 9119; then the Finnhub Nebius
  article) produces: analysis persisted with `subject_relation='customer_or_peer'`,
  `validation_status='rejected'`, `rejection_reason_code='indirect_no_anchor_evidence'`, and
  **no window 2460**.
- An indirect analysis assigned by the story step to a window that holds valid direct evidence
  remains `valid` and joins that window (mechanics unchanged; assignment correctness is
  260715-05).
- No `t_evidence_windows` row exists whose members are all non-`direct`, enforced by a
  regression test over the post-change funnel.
- With story scoping disabled, the existing thesis_builder test suite passes unchanged.
- `assignment_source='fallback'` with an indirect analysis and no direct evidence in the
  fallback target is rejected, not seeded.
- Baseline incidence reported before and after: count of indirect analyses admitted via a
  window anchor and then assigned `new_story`, over a recent production window.

## Resolution

Status: resolved on 2026-07-15.

Root cause: `persist_analysis_and_update_evidence` evaluated the indirect-evidence anchor gate
before story assignment. With story scoping enabled, `_resolve_story_target` could later choose
`new_story` and create a fresh evidence window even though the anchor that admitted the analysis
belonged to a different collecting window.

Fix:
- Story-scoped processing now treats the initial anchor check as provisional and performs the
  authoritative anchor check after `_resolve_story_target`.
- `_resolve_story_target` can now return a symbolic `new_story` target without immediately
  creating an evidence window.
- Indirect evidence assigned to `new_story` or to a target window without valid direct evidence
  is updated to `validation_status='rejected'` with
  `rejection_reason_code='indirect_no_anchor_evidence'`; no new window is seeded.
- Direct evidence can still seed a new story window, and indirect evidence assigned to a window
  that already contains valid direct evidence still joins that window.
- Story-scoping-disabled behavior continues to use the legacy key-scoped anchor check.
- The stale behavior documentation note claiming 260714-03 and 260715-02 were unimplemented was
  removed, and the indirect-evidence rule now documents assigned-target scoping.

Verification:
- `uv run pytest tests/integration/test_thesis_builder_integration.py -q` -> `13 passed`
- `uv run python -m py_compile src\product_components\thesis_builder\repository.py tests\integration\test_thesis_builder_integration.py`

Remaining risk / follow-up:
- This fix does not verify that a `window:<id>` story assignment is semantically correct. That
  cross-story coherence layer is tracked and implemented separately under 260715-05.
