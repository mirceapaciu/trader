# 260615-06 Remove Filter Quality Evaluator direct database access to Shared contracts

## Problem Statement

Filter Quality Evaluator currently reads active watchlist tickers directly from the shared schema. That makes evaluator behavior depend on shared table layout instead of the shared contract surface.

## Verified Evidence

- `src/product_components/filter_quality_evaluator/repository.py:47` reads `shared.<watchlist_table>` directly.

## Expected Behavior

Filter Quality Evaluator should obtain watchlist membership through a shared Instrument Registry API or adapter rather than issuing direct SQL against shared tables.

## Acceptance Criteria

- Filter Quality Evaluator runtime does not query shared watchlist tables directly.
- Watchlist membership used for simulation is supplied through a shared-owned API or adapter.
- Boundary tests fail if Filter Quality Evaluator SQL references `shared.` directly.

## Test Plan

- Run `uv run pytest tests/product_components/filter_quality_evaluator -q`.
- Add focused tests for the shared contract adapter used by Filter Quality Evaluator.
