# 260715-02 Analysis prompt presents provider feed tags as ground-truth attribution; teaser articles form fully off-instrument cards

## Problem Statement

The analysis and triage prompts send the article's `tickers` field to the LLM verbatim, with
no indication of where it came from (`_build_prompt`, `llm_client.py:566`; `_build_triage_prompt`,
`llm_client.py:618`). For articles from Finnhub's per-symbol company-news feed that field is
feed provenance, not attribution: `FinnhubCompanyNewsProvider` unconditionally stamps the
queried ticker on every returned article (260714-01). The model reads `"tickers": ["NVDA"]` as
a statement that the article is about NVDA.

For most articles the headline or summary names the real subject and contradicts a wrong tag.
The failure mode is Motley Fool-style **teaser articles**, whose headlines deliberately hide
the subject company ("Prediction: This Under-the-Radar Dividend Stock Is Going to Skyrocket
After Aug. 4"). With only headline + one-line summary + the tag in the prompt, nothing
contradicts the tag, and the LLM classifies the pair `subject_relation=direct`, inventing
instrument-flavored reasoning.

This escalates 260714-03. There the mislabeled direct was one analysis inside an otherwise
genuine card; card `ffe63506-f02a-5849-ab26-b607fa672344` (NVDA, buy, event_driven, confidence
0.75, created 2026-07-15 10:42 UTC, valid, signal published) shows the failure compounding into
a card with **zero** articles about the instrument:

- **8933** "Prediction: This Under-the-Radar Dividend Stock Is Going to Skyrocket After
  Aug. 4" — a 4.24%-yield dividend stock, plainly not NVDA. Labeled **`direct`**; the
  reasoning credits NVDA with "a strong dividend yield".
- **8937** "Can Penguin Solutions Be the Next 10X Stock?" — PENG. Correctly labeled
  `customer_or_peer`, but it passed the `indirect_no_anchor_evidence` gate because the false
  direct 8933 was already in the collecting window (analyzed 20 seconds earlier). The false
  direct **minted the anchor evidence** that admitted it.
- **8947** "Warren Buffett Bought This New Dow Jones Stock Last Year and His Successor
  Recently Increased the Position by 200%…" — labeled **`direct`**.

The two false directs also satisfied the card-seeding requirement of at least one direct
analysis (`repository.py:423`). Every layer of the 260714-01 indirect machinery worked as
designed; its inputs were poisoned by the tag.

  `news_fetcher.t_input_news_articles`. The same dividend-teaser and Penguin articles also
  arrived via `rss:yahoo_finance:batch:*` with `tickers=[]` — the NVDA attribution exists only
  on the Finnhub copies. None of the three name NVDA/NVIDIA in headline or summary.
- `src/product_components/thesis_builder/llm_client.py:560-569` — analysis prompt article
  payload includes `"tickers": article.tickers` unannotated; `llm_client.py:507-515` grounding
  rules never say the tag is untrusted; `llm_client.py:616-618` — triage prompt likewise.
- `src/product_components/thesis_builder/repository.py:1246-1279` — `_has_anchor_evidence`
  accepts any valid `subject_relation='direct'` analysis in the collecting window as an anchor;
  `repository.py:423` — card seeding requires only an LLM-labeled direct.
- Baseline measurement in 260714-03: 9 of 70 valid directs (13%) never name the instrument in
  headline+summary.

## Expected Behavior

1. **Feed tags are presented as provenance, not attribution.** In both `_build_prompt` and
   `_build_triage_prompt`, the article payload field `tickers` is renamed to `feed_tags`, and
   the grounding rules gain an explicit rule: `feed_tags` records which feed(s) returned the
   article and is NOT evidence the article is about the instrument; `subject_relation=direct`
   requires the company, its products, or its ticker to be explicitly named in the headline or
   summary text.
2. **Deterministic enforcement is 260714-03.** The prompt change reduces incidence; the
   text-verification backstop in `_normalize_analysis_result` (downgrade unverified `direct` →
   `customer_or_peer`, audited) is what guarantees the invariant. The two should land together:
   the backstop makes the ffe63506 outcome impossible (no false direct ⇒ no anchor ⇒ no seed),
   the prompt change keeps the funnel from filling with downgrades.
3. **Regeneration parity.** `reprocessor.py` and `regeneration.py` share the prompt builders,
   so sim funnels stay comparable. Note: changing prompt text changes the
   `backtester.t_llm_analysis_cache` keys, so the first regeneration run after deploy re-pays
   for analyses; this is expected and acceptable.
4. **Scope guard.** The Finnhub provider tagging itself stays (it is the recall channel for
   read-throughs, per 260714-01); nothing upstream of the prompt changes.

## Acceptance Criteria

- The analysis and triage prompt JSON contain `feed_tags` with the provenance grounding rule,
  and no bare `tickers` key presented as attribution. Story-assignment and synthesis prompts
  are unaffected.
- With this issue plus 260714-03 in place, replaying the three ffe63506 articles in order
  against a clean NVDA state produces: 8933-equivalent and 8947-equivalent downgraded (not
  direct), 8937-equivalent rejected `indirect_no_anchor_evidence`, and **no card**.
- A genuinely direct article that names the instrument (e.g. analysis 8947's opposite: "…'very
  few' Nvidia H200 AI chips…" from 260714-03) remains `direct` and byte-identical to today's
  valid path.
- Counterfactual sim (per the sim-schema workflow): re-running a recent `sim_bt_*` window under
  the new prompt shows the "valid direct but instrument never named" rate materially below the
  13% baseline, and the funnel delta is reported before production enable.

## Resolution (2026-07-15)

Root cause: the analysis and triage prompts exposed provider `tickers` as an unqualified
article field. For Finnhub company-feed articles this is feed provenance, not textual
attribution, and teaser headlines could leave the LLM with no evidence contradicting the
wrong tag.

Implemented fix:

- Renamed the prompt article field from `tickers` to `feed_tags` in both `_build_prompt` and
  `_build_triage_prompt`.
- Added prompt grounding rules that `article.feed_tags` are upstream feed provenance only,
  not attribution and not evidence that the article is about the specified instrument.
- Left story-assignment, synthesis, response parsing, and upstream provider tagging
  unchanged.
- Landed with the deterministic enforcement from 260714-03 so prompt failures cannot seed or
  anchor cards.

Verification:

- `uv run pytest tests/product_components/thesis_builder/test_llm_client.py -q` -> 28 passed.
- The combined 260714-03 verification also covered the shared live/reprocess/regeneration
  path that enforces the prompt invariant deterministically.

Remaining risk: changing prompt text intentionally invalidates old
`backtester.t_llm_analysis_cache` keys for regenerated analyses, so the first refreshed sim
window will re-pay the LLM cost.
