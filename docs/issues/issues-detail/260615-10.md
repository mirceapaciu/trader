# 260615-10 Remove Monitoring UI direct database access to Shared contracts

## Problem Statement

Monitoring UI currently reads shared watchlist data directly while composing NewsFetcher-related UI state. That bypasses the shared contract boundary.

## Verified Evidence

- `src/product_components/monitoring_ui/backend/repository.py:728` reads `shared.<watchlist_table>` directly.

## Expected Behavior

Monitoring UI should obtain watchlist membership and other shared data through shared-owned APIs or adapters instead of direct SQL against the shared schema.

## Acceptance Criteria

- Monitoring UI backend does not query shared watchlist tables directly.
- Shared watchlist data used by the UI is supplied through a shared-owned API or adapter.
- Boundary tests fail if Monitoring UI runtime SQL references `shared.` directly.

## Test Plan

- Run `uv run pytest tests/product_components/monitoring_ui -q`.
- Add focused tests for the shared contract adapter used by the Monitoring UI backend.
